## P1/P2 首次使用与简历识别

新增“提供自己的简历 → 源文提取 → AI 识别客观事实 → 核对来源/冲突/缺项 → 私有资料 JSON → 当前授权下现场填写”流程。无需用户手填整份 JSON；已有资料直接复用。

- TXT/Markdown：按段落和编码读取。
- DOCX：读取正文、表格、文本框、页眉页脚，并提示版面核对。
- 文本 PDF：逐页保留文本和位置；扫描或混合 PDF 标记需要视觉/OCR的页。
- 图片：明确交给宿主视觉或可用 OCR，不冒充已运行 OCR。
- 加密、损坏或旧 DOC：清晰报错/交接，不能生成看似完整的空白履历。

提取器保留 source_id 和页码/段落；事实由宿主 AI 依原文组织，技能要求每项保留来源和引文，未知及冲突不猜补。原简历、提取结果、资料 JSON 均保存于仓库外。读取简历不自动授予网站写入权限。

独立前向演练使用明确标为虚构的一份英文简历，实际创建源文和资料文件，读取全部 7 个段落，31 个有来源字段保留引用。演练保留团队指标归属、论文在审和作者次序未知，未编造手机号、工作资格、地区或薪资；因源文为虚构，保留 example_only:true，未进入真实申请。该演练验证宿主 AI 的资料组织流程，不代表程序已调用真实在线核验模型。

## 支持边界

66 项需要本机 Edge 的浏览器控件测试仍缺少现场浏览器验证。Windows 启动器未在 Windows 现场测试，可选 inference-service 未纳入本轮验证。图片与扫描件需要宿主实际提供视觉/OCR；提取器没有捆绑 OCR 模型。任意多页网站导航、iframe、shadow DOM 和尚未适配的控件保留明确交接，不计作覆盖成功。验证码、人脸和本人操作仍由用户完成。

离线检查及合成演练通过，不等于模型账号可用或已证明覆盖大多数招聘网站；仍需代表性平台端到端验证。
